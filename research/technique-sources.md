# Technique sources for the four exercises

Date: 2026-11-09. Status: complete for this pass. Access date of every page in this file: 2026-11-09.

This file records how patient handouts, therapy pages and the protocols of the knowledge base describe the correct way to do each exercise. It then judges what a 2D camera can measure for each point. It uses the verdict scale and the error budget of `form-evidence.md`. It does not repeat them. Quoted source text stays exact.

## How to read this file

- A technique point is one instruction about the way to move. Dose, pain and phase rules stay in `rehab-rules.md`.
- Grade: every source here is evidence level 5 (opinion or local consensus). No trial tested any of these cues. Handout means a hospital, NHS trust or society leaflet. Web page means a clinic or consumer page. Protocol means a surgeon or hospital rehab protocol.
- Population: MPFLR (after MPFL reconstruction), DISLOC (patellar dislocation, mostly not operated), ARTHRO (knee arthroscopy), TKA (total knee replacement), GENERAL (knee exercise, no named condition).
- WEAK: one source only states the point. A WEAK point never goes into the app, not even as a text guide.
- Quote marker: a quote with the sign (f) comes from the answer of the page fetch tool, which cuts quotes to 125 characters. I did not read the full page text. All other quotes come from the text that I extracted from the PDF of the source myself.
- The URL of each source is in the source key. A row cites the source id.
- Verdicts (from `form-evidence.md`): CUE, LOG, NO BUILD. The 2D error is about 9 degrees at best and 9 to 22 degrees in exercise video (F1, F3). Frontal angles are not valid (M2, F4).
- Two words in this file need care. "Camera verdict" is only about what the app can measure. It never says that a movement is right or wrong.

## What the app can show without judging

Rules for all lines below: a text guide line states an instruction and its source. It never says that a movement is right or wrong. It carries a number only when a clinician sets it. Every WEAK point stays out. A clinician must review every line before patient use.

### Straight leg raise

## Decision for the user

The request is live feedback on whether the execution is correct. The sources describe technique well, but they do not make it measurable. Three facts decide this.

1. Of 34 technique points, only 3 are CUE, and all three already exist in `form-evidence.md` (knee bend limit and arc end). The handouts add no new measurable limit. They add text guide lines.
2. The sources disagree on every number. Lift height runs from 5 cm to 40 cm. Hold time runs from 2 to 10 seconds. None is an MPFLR value. The 2D error is as large as the effects for the knee straight and for the knee inward.
3. The guardrails forbid the words correct and incorrect, a verdict colour and a pass or fail. These rules block "is my execution correct".

Options:
- A. Text guide only, plus the 3 CUE items, plus LOG for the clinician. The guide shows each line with its source. A clinician sets every number. This keeps all guardrails.
- B. Option A, plus per-patient limits that the clinician sets for lift height and hold time. Then lift height and hold time can become cues. This needs a new protocol field and a clinician review. It keeps the guardrails.
- C. Show a form judgement from the camera (for example "knee straight" or "knee inward"). This breaks the guardrails and the error budget. I do not recommend it.
